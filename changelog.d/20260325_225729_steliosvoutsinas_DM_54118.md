### Added

- PostgreSQL backend. A single image now serves Postgres, Qserv, or BigQuery, selected by the `BACKEND` environment variable: Postgres over a direct JDBC connection, Qserv and BigQuery via the Kafka bridge.
- `PluginFactory-pg.properties` and `PluginFactory-qserv.properties`, so the deployment selects `PluginFactory-<backend>.properties` for any backend.
- `Backend` enum to read and validate the `BACKEND` variable, and `TapConfig` as the single place service configuration is read.
- `PostgresUploadManager`, which creates `TAP_UPLOAD` tables in the Postgres data database; the Kafka backends still stage uploads to object storage.
- `jdbc/tapschemauser` datasource for `tap_schema` reads, used by both runners.
- `AbstractRubinAdqlQuery`, shared by the Qserv and Postgres ADQL translators.

### Changed

- Source reorganised into domain packages (`config`, `query`, `execution/{direct,kafka}`, `schema`, `storage`, `upload`, `validation`, `logging`, `ws`); the `impl` and `dialect` packages are gone.
- `QueryJobManager` selects a direct thread-pool executor for Postgres or the Kafka executor for Qserv and BigQuery.
- `KafkaContextListener` skips Kafka setup for Postgres, and now fails startup on a Kafka misconfiguration instead of logging and continuing.
- `RubinTapSchemaDAO` advertises the Qserv and SciSQL functions only for the Qserv backend.
- Renamed `RubinQueryRunner` to `KafkaQueryRunner`, dropped the `Impl` suffix from the ADQL classes, and renamed `MaxRecValidatorImpl` and `RubinUploadManagerImpl` to `RubinMaxRecValidator` and `RubinUploadManager`.
- `jdbc/tapuser` is sized from `tap.maxActive` instead of an unset property, so the Postgres query pool is actually configured.
- Updated `web.xml` and the `PluginFactory` files for the new packages.

### Removed

- `jdbc/qservuser` datasource: Qserv queries run in qserv-kafka, not in this service.
- `src/intTest`: hadn't compiled or run since 2018 and was never part of CI.
